Patches for the vendored Spaces mod

Narrative

nerd-herd builds its sidebar on a copy of Herdr's shipped Spaces mod. scripts/vendor-spaces.ts makes that copy and applies nerd-herd's own changes to it. The build then bundles everything into one file, so a change made to the built mod is lost on the next build.

Other people publish changes to Herdr's Spaces mod as patch files. One example is the jj patch from herdr-app-jj, which shows a Jujutsu (jj) repository's bookmark in the sidebar and opens a menu with jj workspace items. Dannel wants such patches to survive every build. The vendor step therefore applies the patch files kept in patches/spaces/ to Herdr's Spaces mod before nerd-herd's own changes.

Claims
  • The vendor step applies every patch in patches/spaces to Herdr's Spaces mod, in file-name order
  • A patch that does not apply stops the vendor step and names the patch
  • The vendored Spaces file is what the vendor step produces
  • The vendored Spaces asks jj before git about a space's repository

Module Definitions

Spaces patching

scripts/vendorPatches.ts: applies patch files to the text of Herdr's Spaces mod with the patch program, and names the patch that does not apply.

Vendor step

scripts/vendor-spaces.ts: reads Herdr's Spaces mod, applies the patches in patches/spaces/, then nerd-herd's own changes, and writes src/mod/vendor/herdrSpaces.js or the path given as its first argument.

Ambiguity Resolution
  • Patch order against nerd-herd's changes: patches apply first, because a published patch is written against Herdr's shipped Spaces mod, not against nerd-herd's copy.
  • The jj patch's text: the published patch was written for a clone with project icons. Its import line names home and it changes a roots() method, and Herdr's shipped Spaces mod has neither. The copy in patches/spaces/ adds readTextFile to the shipped import line and leaves out the roots() hunk, as the patch's own install steps direct. Herdr 0.1.16 rewrote check(), so the copy places the jj lookup at the start of the new check(); the record it stores has the same fields as 0.1.16's git record.

Herdr's installed Spaces mod and the patches in patches/spaces/
When

Then

The sidebar asks jj first

Given
The vendored Spaces file
When
Its check() method is read
Then
It calls checkJj() before its first git command (Herdr 0.1.16 starts with git rev-parse; 0.1.14, which the published patch targets, started with git status)

Error paths

A patch that does not apply is named

Given
A patch whose context is not in the Spaces text
When
It is applied
Then
The step fails with an error that names the patch file
